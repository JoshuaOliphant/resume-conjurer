# Guided grimoire building

Open **Build my grimoire** from the document workbench after importing and preparing the master resume. Answer target roles and ownership, examples with personal contribution and delivery status, and phrasing preferences. Optional text, DOCX, or text PDF sources are imported individually for local review. Originals remain recoverable. Remove a source from onboarding without deleting its original.

Select exact line excerpts. The page shows the source SHA-256, original hash and extraction warnings, plus the complete request and its Claude destination. Page loads, imports, source review, edits and acceptance make no model call. **Draft with Claude** makes one tool-free SDK request from an empty temporary directory, with a three-turn, $0.10 and 90-second bound. Actual duration, token counts and billed cost are recorded; missing provider measurements remain unavailable.

Unaccepted answers, excerpts, proposals and edits live in revision-checked `onboarding.json`. Acceptance writes only `grimoire.md` through the existing document history store. A source or grimoire revision conflict preserves submitted text for recovery. Missing per-application `evidence.md` is optional and reads as empty; master-resume line IDs remain unchanged.

The ledger labels career spans source-linked, answers user-attested, and unresolved claims needs review. These labels do not establish semantic truth. Exact quote, number, role-date, attribution and status checks run locally. Related excerpts with conflicting metrics or delivery status remain questions; no source wins automatically. Negated or ambiguous delivery wording stays unknown. A voice sample cannot support a career accomplishment, even if another factual source has the same number.

Style acceptance intentionally uses a constrained vocabulary of short instructions, such as “Use concise language” or “Avoid hype.” The model's `preference` label grants no trust. Mixed factual/style sentences, unsupported headings, arbitrary new factual wording and unrecognized preferences stay needs review. Restate a preference as a short style instruction or use the ordinary manual document editor after accepting. Enter factual additions explicitly into career answers or selected evidence and review a fresh draft; a blanket edit attestation cannot supply factual support. Unrecognized English wording may need human review; these checks are not a semantic classifier.

Review is bounded to 256 excerpts, 8 KiB per excerpt, 64 KiB source text, at most 16 optional files and 64 KiB outbound request. Oversized optional selections are rejected before originals or onboarding state are persisted. Existing oversized sources can be removed from the page to recover. The upload byte cap applies before multipart parsing. No OCR or original-layout recovery is promised. Extraction and model failures leave accepted sources and existing drafts intact.

No TypeSafe request occurs in this flow. Private career excerpts require separate, precise consent before any future Jev support check. Source-linked onboarding text is not generation evidence: factual additions must still enter master/evidence and be checked by the normal tailoring pipeline.
